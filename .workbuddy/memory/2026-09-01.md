## 创建 Java 技能体系（9 个技能）

在 `skills/java/` 下建立分工化 Java 技能集，规范源为仓库 `standards/`（7 份）+ `AGENTS.md`。

**9 个技能**（SKILL.md 精简入口 + references/ 详细手册，共 28 个 md 文件）：

| 技能 | 目录 | 定位 |
|------|------|------|
| `java:reference` | `java-reference/` | 规范总索引、硬性红线速查、冲突裁决顺序、路由表 |
| `java:project` | `java-project/` | 模块结构、Maven POM/BOM/parent、构建配置 |
| `java:design` | `java-design/` | 领域建模、契约设计、架构决策 |
| `java:develop` | `java-develop/` | 六阶段领域初始化、变更工作流、代码模板 |
| `java:test` | `java-test/` | 契约测试、测试约定（JUnit5+AssertJ+Mockito） |
| `java:check` | `java-check/` | L0-L5 验证分层、评审清单、安全/性能风险 |
| `java:spring` | `java-spring/` | Spring 专项 + 本仓库适用边界 |
| `java:project-upgrade` | `java-project-upgrade/` | 工程基线升级 |
| `java-tool-upgrade` | `java-tool-upgrade/` | 基础组件/依赖升级 |

**两个升级技能的区分原则**（用户确认）：
```
改变项目运行/构建基线  → java:project-upgrade
改变项目使用的基础组件 → java:tool-upgrade
```
同时涉及时主流程归 project-upgrade，过程中调用 tool-upgrade。用户明确要求
升级类技能不再继续拆分，避免碎片化。

**命名约定**：frontmatter `name` 用 `java:xxx`（用户表格指定），目录名用 `java-xxx`
（用户目录结构指定）。

**内容依据**（从源码确认的项目基线）：
- JDK 25 / Maven ≥3.9.0 / 7 个 Maven 模块（bom, parent, base, core, console, kernel, platform）
- Jakarta REST + jakarta.transaction.Transactional（禁 Spring MVC 注解与 Spring 事务注解）
- MyBatis-Plus（单表、禁 join、禁 Mapper XML）、MapStruct + BaseMapperConfig
- Lombok 1.18.46 / MapStruct 1.6.3，annotationProcessorPaths 中 Lombok 必须在 MapStruct 之前
- 状态码九字符 `MODULE(3)+CATEGORY(2)+LOCAL(4)`；`StatusCode.message()` 返回带 `enValue()`/`cnValue()` 的对象
- 测试：包级私有类、方法名 lowerCamelCase 行为短语无 `test` 前缀、AssertJ

**Spring 版本快照（2026-09 查证）**：Boot 4.1.1（2026-08-20，Framework 7.0.9，Java 17-26）；
4.0.x OSS 支持至 2026-12；3.5.x OSS 支持已于 2026-06-30 结束；3.x→4.x 必须先升到 3.5，
且 4.x 模块化移除了自动配置类的 public 成员。

**验证**：9 个 frontmatter 全部合法，31 个本地链接零断链。
