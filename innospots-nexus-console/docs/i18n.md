# Console 国际化

Console 国际化遵循 Pactor 的服务端本地化协议：页面 YAML 保留作者态，Next.js
服务端按请求语言加载语言包并通过 `localizePageDsl` 生成下发态 DSL；浏览器只渲染
最终文案，不自行加载业务语言包或按 YAML 路径查找词条。

## 资源目录

语言包由 `innospots-nexus-platform` 随应用打包，位于
`innospots-nexus-platform/src/main/resources/i18n/console/`：

```text
i18n/console/
├── namespaces
├── access/
├── audit/
├── auth/
├── common/
├── dictionary/
├── invite/
├── menu/
├── organization/
├── platform-user/
├── plugin/
└── role/
```

`namespaces` 每行声明一个 namespace，并决定默认加载顺序。每个 namespace 使用
Spring MessageResource 风格文件：

- `messages.properties`：默认语言 `zh-CN`
- `messages_en.properties`：语言级英文回退
- `messages_en_US.properties`：可选地区级覆盖
- `messages_zh.properties`、`messages_zh_CN.properties`：可选中文语言级/地区级覆盖

加载顺序为：默认文件 → 语言文件 → 地区文件。后加载的文件覆盖同 key，缺失 key
继续保留前序文件中的值。语言选择只决定覆盖文件，不改变默认文件的回退职责。

## 词条键

key 使用稳定语义，不使用 YAML 字段路径、数组下标或内容哈希：

```properties
common.page.login.title=登录
common.ui.cancel=取消
role.role-list.title=角色管理
role.role-list.summary.count=共 {{count}} 个角色
```

约束：

- 每个 key 必须以所属 namespace 开头。
- 不同 namespace 不得声明相同完整 key。
- 中英文语言包必须具有相同的 key 集合。
- 禁止 `.body.`、`.children.`、`.props.`、`.events.`、`.columns.` 等 DSL 路径段作为 key。
- 禁止根据源文案生成的 FNV/hash key。

## 页面 YAML

业务页面优先使用 Pactor 的属性引用语言包方式，在**文案属性值**上声明
`$i18n.key`；不要为了国际化把属性改成页面级路径：

```yaml
page:
  id: role-list
  title: '$i18n{role.role-list.title:角色管理}'
i18n:
  namespaces: [common, role]
body:
  type: Button
  props:
    text: '$i18n{common.ui.cancel:取消}'
```

规则：

- 静态展示字段使用 `$i18n{key:fallback}`；key 为稳定语义键，不是 YAML 路径。
- `fallback` 写默认语言源文，词条链全部缺失时由 Pactor 使用。
- Pactor 1.58 已移除 `i18n.bindings`；带动态参数的文案使用 `$i18n` 对象。
- 转换后顶层 `i18n` 会被移除，作者态 `$i18n` / `bindings` 不得残留在下发态。

```yaml
# 少量局部文案也可用属性内联 messages
text:
  $i18n:
    messages:
      zh-CN: 保存
      en-US: Save
```

依赖运行时数据的动态文案使用运行时表达式：

```yaml
text: "${t('role.role-list.summary.count', { count: data.roles.total })}"
```

### Console 可翻译字段

`src/server/i18n-registry.ts` 在 Pactor
`createDefaultTranslatableFieldRegistry()` 基础上注册 Console 组件字段：

- `Button`、`Text`、`Typography`、`Field`、`Input`、`Textarea`、`Select`、
  `RadioGroup`、`FilterSelect` 的展示属性、选项 label 与校验 message。
- `Breadcrumb`、`Descriptions`、`Tabs` 的 label/title。
- `Table.columns[*].title`、`Drawer` 的标题与按钮文案、`Alert` 文案。
- `Header` 的语言切换项与用户菜单项 label。
- `message`、`confirm`、`overlay.open` 动作参数。
- `Table.columns[*].cell`、`Tabs.items[*].children/extra` 与
  `overlay.open.params.overlay.content` 内嵌 DSL 子树，内部仍按组件属性
  `$i18n.key` 转换。

新增组件类型时，应在该注册表声明可翻译展示字段，而不是新增 YAML 路径绑定，
也不要在浏览器端增加第二套 key 查找逻辑。

## 公共接口

```http
GET /api/public/i18n/bundles
```

该端点使用 `@EndpointModule(ignoreAuth = true, ignorePermission = true)`，无需登录
或功能权限。查询参数：

| 参数 | 说明 |
|------|------|
| `appId` | 应用标识，缺省或 `console` |
| `locale` | `zh-CN` / `en-US`，支持 `zh`、`zh_CN`、`en`、`en_US` |
| `namespaces` | 逗号分隔 namespace；缺省加载全部 |
| `release` | 发布标识，仅接受 `[A-Za-z0-9._-]{1,64}` |

语言优先级：显式 query > `locale` Cookie > `Accept-Language` > `zh-CN`。缺少
`locale` 时返回中文默认包。

响应为统一 `R<T>`；Pactor 消费的 `data` 为 `simple-v1`：

```json
{
  "appId": "console",
  "locale": "en-US",
  "release": "console-ui",
  "format": "simple-v1",
  "bundles": {
    "common": {
      "version": "<sha256>",
      "messages": {
        "common.page.login.title": "Sign in"
      }
    }
  }
}
```

## Next.js 对接

`innospots-nexus-ui-console` 不维护第二套 locale 解析、消息查找或 DSL 路径翻译：

1. `src/pactor/locale.ts` 只声明 Pactor `LocaleResolverConfig`。
2. `resolveRequestLocale` 统一解析 query、`locale` Cookie 与 `Accept-Language`。
3. `ApiMessageProvider` 调用 Java 端点；`envelopeFetch` 只负责拆解 `R<T>.data`。
4. 当前语言与默认语言一起组成 `LanguageBundles`，由 `localizePageDsl` 执行显式回退。
5. `src/server/i18n-registry.ts` 只扩展 Pactor 可翻译字段注册表。
6. `/api/i18n/bundles` 暴露同一 `MessageBundleSet`，供外部渲染服务复用。
7. `/api/i18n/locale` 写入通用 `locale` Cookie，随后整页刷新并重建 sitemap/页面。
8. sitemap、布局、懒加载页面均在服务端转换为 localized DSL；响应带 `localization`。

Java 服务不可用或返回非 `simple-v1` 协议时，页面回退到 YAML 中文源文；非法显式
locale 不会被静默吞掉。

## 代码内文案

React 组件直接使用 Pactor Runtime：

```tsx
const { t } = useI18n();
return <button>{t("common.ui.cancel")}</button>;
```

自定义 action 使用运行时上下文：

```ts
new Error(ctx.context.i18n.t("common.ui.request-failed"))
```

`I18nText` 只用于解析后端 `I18nObject`（`locale → 文案`）数据，不是语言包
resolver；它优先使用当前 Pactor locale/defaultLocale。不要新增 `useUiText`、
hash 文案 key 或平行的 DSL 本地化模块。

## 校验

```bash
mvn validate
mvn -pl innospots-nexus-console -am \
  -Dtest=MessageBundleLoaderTest,MessageBundleServiceTest,I18nStatusCodeTest,I18nBundleEndpointContractsTest \
  -Dsurefire.failIfNoSpecifiedTests=false test
mvn -pl innospots-nexus-platform -am \
  -Dtest=PlatformMessageBundlesTest \
  -Dsurefire.failIfNoSpecifiedTests=false test
```

修改资源后应确认：索引包含全部目录；中英文 key 集合一致；所有 key 使用所属
namespace 前缀；不存在 DSL 路径 key 或 hash key。
