# 功能开发、修改、Bug 修复与重构

## 定位

负责**实现代码**。设计结论来自 `java:design`，验证动作交给 `java:check`。
本技能的硬约束只有一条，但必须无条件执行：

> **每批 Java 源文件改动之后立即运行 `mvn clean compile`。**
> 不得延后到任务末尾，不得在源码不可编译时继续添加功能，
> 不得下调 `maven.compiler.release` 以迁就本地旧 JDK（应报告环境不匹配）。

## 任务类型与流程

| 任务 | 流程 | 出口 |
|------|------|------|
| 新业务领域初始化 | [六阶段领域初始化](references/domain-initialization.md) | `java:check` 全量验证 |
| 在已有域加功能 | [变更工作流](references/change-workflow.md) | 聚焦测试 + `mvn clean compile` |
| 修 Bug | [变更工作流](references/change-workflow.md) 的缺陷分支 | 复现测试 + 全量测试 |
| 重构 | [变更工作流](references/change-workflow.md) 的重构分支 | 行为不变证明 + 全量测试 |

## 六阶段领域初始化（新建业务域）

严格按阶段推进，**逐阶段评审通过后才进入下一阶段**。
禁止先把整棵包树生成出来再倒推合理性。

```text
1. 定义实体数据结构      → 实体门禁
2. 定义 DAO 契约         → DAO 门禁
3. 定义领域契约          → 领域门禁（枚举 / Request / VO / model / 事件 / 状态码）
4. 定义转换边界          → 转换器必要性判断
5. 定义端点边界          → 端点门禁
6. 按需添加 Operator / Service
```

### 阶段零：确认归属与词汇（前置，不属于六阶段）

在写任何源文件之前：

1. **确认归属** — 哪个 Maven 模块拥有这个能力；是业务专属还是可复用基础设施；
   记录是平台级、租户级还是工作区级；相邻域有哪些；哪些行为现在要、哪些有意推迟。
2. **建立词汇** — 主业务概念与关联概念、归属范围、技术 ID 与稳定业务键的区别、
   `state`/`status`/`mode`/`type` 的确切含义、各操作的命名、属于相邻域不得借用的概念、
   每个失败的归属方与状态码归属。
3. **遗留工程只作行为参考** — 可用于理解业务术语、常见操作、生命周期、树/成员/
   排序/状态行为、必须稳定的数据、历史边界情况与受保护记录。
   **禁止**复制或移动遗留源文件、机械复刻包结构、沿用过时框架注解与依赖、
   无当前理由地保留反范式或重复字段、把现在分属不同域的概念合并、复刻遗留 POM。
4. **初始面保持最小** — 只有当前任务确实需要时才加 `model`/`converter`/`operator`/
   `service`/`event`/`handler`。

```text
<domain>
  ├── dao
  ├── domain
  │   ├── entity
  │   ├── enums
  │   ├── request
  │   └── vo
  └── endpoint
```

### 测试先行顺序

```text
1.  写实体契约测试
2.  运行并确认因缺少契约而红灯
3.  实现实体
4.  写 DAO 泛型绑定测试
5.  实现 DAO
6.  写 Request / VO / 枚举 / 状态码 / 端点契约测试
    （若本域新增失败，需覆盖全码形状、本地唯一性、元数据、HTTP 映射、
      类型化异常构造与 cause 保留）
7.  运行并确认红灯
8.  实现领域 record、状态枚举（如需）与端点
9.  重跑聚焦测试直到通过
10. 跑全量工程验证
```

不得为了让偶然的实现通过而削弱有效测试。
测试暴露出的既有无关问题应与预期红灯区分开，并用 `-am` 之类的 reactor 构建处理
本地依赖产物过期。

## 缺陷修复分支

```text
复现     → 先写一个能复现缺陷的测试（红灯）
定位     → 找到拥有该失败语义的边界（不是报错的那一层）
修正     → 在正确的边界改：校验归属、异常归属、事务边界、并发保护
验证     → 聚焦测试转绿 + 全量 mvn test
回归     → 确认没有削弱其他测试的断言
```

修 Bug 时额外检查：

- 是否只是掩盖症状（吞异常、放宽校验、加 try-catch 返回默认值）
- 失败是否应在更窄或更宽的边界抛出
- 是否引入了对兼容面的破坏
- 是否需要新增状态码（先搜现有目录）

## 重构分支

```text
定目标   → 明确重构后的边界，而不是"让代码好看点"
保行为   → 先用测试锁住现有外部可见行为
小步走   → 每批改动后立即 mvn clean compile
守契约   → 公共兼容面的改动必须先出迁移方案
验证     → 全量 mvn test + java:check
```

重构的红线：

- 不得把公共兼容面的改动当作内部重构
- 不得顺手改 `nx_` 表名、稳定业务键、实体 ID 前缀、事件类型串、状态码
- 不得为了让测试通过而削弱断言
- 不得复制遗留结构来"对齐"旧工程

## 严格禁止

| 禁止 | 说明 |
|------|------|
| 生成不能编译的代码 | 每批改动后必须 `mvn clean compile` |
| 返回伪造成功数据 | 推迟实现用 `TODO` + `UnsupportedOperationException` |
| 裸 `TODO` / `FIXME` | 必须说明缺什么与未来归属 |
| 静默吞掉异常 | 不得为了返回成功而 catch |
| 逐层重复记录同一失败 | 只在增加上下文处或最终处理处记录 |
| 日志中出现敏感值 | 密码、令牌、密钥、解密载荷、敏感配置 |
| 在 `domain.request` / `domain.vo` 写 class | 必须是 record |
| DAO 中写 join 或 Mapper XML | 单表约束 |
| 端点使用 Spring MVC 注解 | 只用 `jakarta.ws.rs` |
| 复制遗留源码/POM | 遗留工程只作行为参考 |
| 顺手更新模块 `SKILL.md` / `references/` | 仅开发者显式请求整体扫描时才更新 |

## 出口

所有实现完成后交 `java:check` 执行编译、测试、规范、依赖与安全检查。
